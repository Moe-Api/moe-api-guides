# New API 下游接入 Moe API

这是一份面向 New API 管理员的接入检查清单。名称、地址、模型和价格均应以当前服务商后台信息为准。

## 接入前确认

- 确认下游服务提供的协议：OpenAI Chat Completions、Responses、Anthropic Messages 或其他协议。
- 确认 endpoint 是否需要 `/v1`、特殊请求头、组织标识或渠道标识。
- 确认模型映射、上下文长度、流式响应和工具调用能力。
- 确认余额、限流、超时、重试和错误码行为。

## 配置流程

1. 在 New API 中创建下游渠道，选择与实际协议匹配的类型。
2. 填入服务商 endpoint 和密钥；密钥只在后台输入，不写入仓库。
3. 配置模型映射，避免把不支持的模型名暴露给上游用户。
4. 设置合理的超时、重试次数和并发限制。
5. 用短文本分别测试非流式、流式、长上下文和错误响应。
6. 查看 New API 日志与下游请求 ID，确认计费和返回内容一致。

## 常见问题

- 404：协议路径或模型映射错误。
- 401/403：密钥、权限或请求头不匹配。
- 429：下游或 New API 的限流生效，需要降低并发或调整配额。
- 5xx：先区分 New API、反向代理和下游服务的日志，再调整超时。

## 安全

不要在 issue、截图和日志中公开 API Key、Cookie、完整请求体或用户内容。生产环境建议使用独立密钥、最小权限和可撤销的渠道配置。
